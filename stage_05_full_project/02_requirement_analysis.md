# 需求分析

> 周次：Week 1-2 ｜ 投入：12小时 ｜ 前置：01_project_selection.md

---

## 目标

把一页纸章程变成**可执行的需求文档**：场景清单、意图体系、测试集v1、验收标准。**没有需求文档就动手写代码，是个人项目烂尾的头号原因**。

---

## Step 1: 意图体系设计（3小时）

把用户问题世界收敛成有限的意图枚举（复用Stage 3的分类路由）：

```python
class Intent(str, Enum):
    POLICY_QUERY = "policy_query"        # 制度查询（纯RAG）
    MULTI_CONDITION = "multi_condition"  # 多条件推理（RAG+链式）
    PROCESS_GUIDE = "process_guide"      # 办事流程（RAG+结构化输出）
    TOOL_QUERY = "tool_query"            # 实用工具（工具调用）
    CHITCHAT = "chitchat"                # 闲聊/超范围
```

每个意图写清楚**边界和路由依据**：

| 意图 | 典型问题 | 判定特征 | 禁止路由到 |
|------|---------|---------|-----------|
| POLICY_QUERY | "转专业要什么条件" | 单一事实查询 | MULTI_CONDITION |
| MULTI_CONDITION | "挂过科重修85分还能评二等奖学金吗" | 需组合≥2条规则 | POLICY_QUERY（答不全） |
| PROCESS_GUIDE | "报销需要哪些材料" | 期望步骤清单 | — |
| TOOL_QUERY | "明天三教有空教室吗" | 需实时数据 | 任何RAG |
| CHITCHAT | "帮我写情书" | 超范围 | 必须礼貌拒绝 |

**边界case清单**（分类器最容易错的地方，写10条进测试集）：

```
"挂科了还能入党吗" → POLICY_QUERY（单条件，别看到"挂科"就路由到多条件）
"大二转专业和大三转专业要求一样吗" → MULTI_CONDITION（两条规则对比）
"学校WiFi密码多少" → TOOL_QUERY还是POLICY_QUERY？（按语料实情定，写死）
```

## Step 2: 用户故事与验收标准（3小时）

每个核心场景写成**用户故事+可验证的验收条件**（不是"支持智能问答"这种空话）：

```markdown
### US-01 制度查询（P0）
作为学生，我想问"XX奖学金的评定条件"，
得到带文件出处的准确答案，这样不用翻几十页PDF。
验收：
- [ ] 答案含[1]式引用，引用段落确实包含答案依据
- [ ] 语料中没有的问题回复"未在现行文件中找到"，不编造
- [ ] P95 < 3s

### US-02 多条件推理（P0）
"我挂过一科，重修85分，绩点3.2，能评二等奖学金吗"
验收：
- [ ] 同时引用评定办法中"成绩要求"和"挂科限制"两条
- [ ] 结论给出明确判断和依据条款号
- [ ] 若规则模糊（文件没写重修成绩怎么算），明确指出模糊点而不是猜

### US-04 查空教室（P1，工具）
"周三下午三教有空教室吗"
验收：
- [ ] 调用课表工具而非检索
- [ ] 返回结构化教室列表
- [ ] 工具失败时明确提示"课表服务暂不可用"

### US-06 反馈闭环（P0）
每个答案下方有 👍/👎 和"纠错"入口
验收：
- [ ] 👎必附原因标签（答错了/引用错了/看不懂/其他）
- [ ] 数据落入后台BadCase表
```

P0/P1/P2排序原则：**P0=没有它项目不成立，P2=锦上添花**。12周只承诺P0+P1。

## Step 3: 测试集v1（4小时）

**现在就建**（不是写完系统再建）——需求阶段的测试集最客观：

```
来源配比（目标150条，v1先做80条）:
- 用户访谈收集的真实问题     30条（金标准！）
- 从文件人工出的题           30条
- LLM生成+人工修订           20条（复用Stage 2-06三步法）

类型覆盖:
  事实查询40% | 表格数字15% | 多条件推理15% | 流程类15% | 工具类10% | 不可回答5%
```

每条格式（复用Stage 2测试集schema，新增intent字段）：

```json
{
  "id": "edu_023",
  "question": "重修成绩会覆盖原成绩吗",
  "answer": "覆盖，按最高分计（依据：《本科生学籍管理规定》第十二条）",
  "source_quote": "重新修读课程的成绩按实际成绩记载...",
  "intent": "policy_query",
  "type": "fact",
  "expected": "answerable"
}
```

## Step 4: 非功能需求（2小时）

直接复用前阶段成果，写死数字：

| 维度 | 指标 | 出处 |
|------|------|------|
| 检索质量 | CR≥85/CP≥80/Faith≥90 | Stage 2达标线 |
| 端到端 | P95<3s，TTFT<1s | Stage 4 |
| 稳定性 | 非5xx 99.9%，降级<2% | Stage 4 SLO |
| 成本 | <$0.01/请求（学生项目预算） | Stage 4-05 |
| 隐私 | 不存任何个人身份数据，日志脱敏 | 本阶段新增红线 |
