# 技术影响力建设

> 周次：Week 7-8 ｜ 投入：15小时

---

## 目标

把12个月的积累变成**可被搜索到的公开资产**：3篇技术博客 + 完整的GitHub门面。面试官在面试前就会看到它们。

---

## Step 1: 三篇博客（每篇3小时写作+1小时改）

### 第1篇：数据故事（Stage 2产出）

```
标题: 《从62%到91%：工业级RAG检索优化的完整实录》
结构:
  1. 翻车现场: 三个真实BadCase(表格腰斩/型号混淆/指代丢失)
  2. 基线: 玩具级架构+62%的CR
  3. 五步迭代: 父子切分→混合检索→RRF→重排→查询改写
     每步: 为什么做/怎么做/数字变化
  4. 消融实验表(原样贴)
  5. 仍在解决的问题(真诚是最大的差异化)
```

### 第2篇：稳定性故事（Stage 3-4产出）

```
标题: 《0.9的5次方=59%：让Agent活到生产的工程手段》
核心: 59%→99%的六件套，配混沌实验数据
```

### 第3篇：产品故事（Stage 5产出）

```
标题: 《500个真实用户教会我的事：一个校园Agent的诞生》
核心: 数据→上线→反馈→4版迭代, 用户视角的坑
（这篇在创业公司面试最值钱）
```

**写作纪律**：
- 每篇必有**自己的数据和图表**（这是和营销号的本质区别）
- 先发草稿给两位技术朋友挑刺，再发布
- 平台：知乎/掘金/个人博客任选，**内容大于平台**

---

## Step 2: GitHub门面（4小时）

仓库主页 = 你的第二简历：

```markdown
# campus-assistant README 结构
1. 一句话 + 演动图(GIF 15秒)     ← 没有动图的仓库没人看完
2. 核心指标表(直接贴最终版)
3. 架构图(mermaid)
4. Quick Start(3条命令跑起来, 配docker-compose)
5. 技术深挖索引(链到三篇博客)
6. 版本演进表(v0.1→v1.0)
7. 已知限制与Roadmap
```

加分动作：
- 把通用部分抽成小工具单独开源（如 `parent-child-chunker`），证明工程抽象能力
- Pin三个仓库：主项目 + RAG管线 + 学习路线本身（你正在用的这个repo！）

---

## Step 3: 表达训练（3小时）

- 每篇博客写完后**朗读一遍并录音**，改掉所有念不通的句子
- 把第1篇缩成5分钟闪电演讲稿（技术分享会/群分享用得上）
