# 面试策略与岗位画像

> 周次：Week 1 ｜ 投入：8小时

---

## 目标

搞清楚"对面坐的是谁、他要什么"，再决定怎么讲你的故事。**面试不是考试，是供需匹配**。

---

## Step 1: 岗位画像（2小时）

2026年大模型应用岗的四种面孔：

| 岗位 | 关心什么 | 你的对口弹药 | 危险区 |
|------|---------|-------------|--------|
| **大厂Agent平台组** | 工程深度、稳定性、规模 | Stage 3-4（状态机/容错/SLO） | 会追LangGraph底层、并发细节 |
| **AI创业公司（B端产品）** | 全栈速度、落地能力 | Stage 5全项目（一个人闭环） | 会追"真用户怎么来的、留存如何" |
| **传统企业AI转型岗** | 可靠、成本、集成 | Stage 2 RAG + Stage 4成本 | 会追私有化部署、数据安全 |
| **大厂搜索/推荐转RAG** | 检索质量、评估方法 | Stage 2全套（指标硬核） | 会追向量索引原理、召回理论 |

**动作**：在招聘网站收集20个目标JD，做成词频表——你会发现高频要求和你手里的牌高度重合（RAG/Agent/评估/稳定性），把每个高频词映射到你项目的具体章节。

---

## Step 2: 你的故事主线（3小时）

所有回答都汇入一条主线：

```
"我发现真实文档场景里玩具级RAG完全不可用
 → 所以我做了工业级管线（解析→父子切分→混合检索→重排）
 → 用评估集驱动迭代拿到数字（CR 84→91%）
 → 但单轮问答满足不了复杂规则推理，上了LangGraph工作流
 → 概率系统必须工程兜底，建了容错+监控+SLO
 → 最后放到500个真实用户面前，用反馈闭环迭代了4版"

= "我不只会搭Demo，我会让AI系统在生产里活下来" —— 这正是市场最缺的
```

**三个必须烂熟于心的数字故事**（每个都是"起点→动作→结果"）：

1. 检索：CR 62%→91%（哪些手段、每步贡献多少）
2. 稳定：0.9⁵=59%的问题怎么被工程手段拉到生产可用
3. 用户：👍72%→87%（归因循环、4次发版）

## Step 3: 面试流程与评分逻辑（2小时）

```
典型4轮:
1. 简历面/HR面    → 项目真实性、动机、稳定性      (你的主线故事)
2. 技术一面       → 项目深挖 + 基础(Python/异步/LLM API) (30问题库)
3. 技术二面       → 系统设计 + 场景题              (02/03文档)
4. 交叉/总监面    → 工程判断力、学习能力、潜力     (讲trade-off)
```

**评分真相**：没有标准答案，考官在打四个分——**深度（挖三层还在不在）、真实性（细节经不经得起追问）、trade-off意识（知道代价）、表达（结构化）**。

回答模板（练到本能）：

```
结论先行 → "我的做法是X"
分点展开 → "原因有三：..."
承认代价 → "代价是Y，我当时权衡后认为值得，因为..."
边界认知 → "如果场景变成Z，我会换方案W"
```

## Step 4: 30问项目深挖题库（1小时，先自测再补02/03）

对着题库口头自测，**答不流畅的标记**，05文档模拟面试重点练：

```
数据与RAG:
1. 你的表格为什么会被切坏？具体怎么发现的？(答:行数守恒断言+BadCase)
2. 父子切分的两个粒度怎么定的？调过参数吗？数据？
3. BM25和向量的分数怎么融合？为什么不能直接加权？
4. Rerank为什么能救回被向量埋没的结果？代价是什么？
5. 评估集怎么保证不泄漏？（生成→修订→版本冻结）
6. Faithfulness 93%怎么算出来的？剩下的7%是什么？
7. 换一份新语料，你的管线要改什么？多久？

Agent与工程:
8. 为什么不用ReAct让模型自己决定流程？
9. 你的循环重试上限是多少？为什么是这个数？
10. 结构化输出失败率多少？三层防线分别是什么？
11. 熔断器的三个状态怎么转换？阈值怎么定？
12. async def里写了requests会怎样？怎么发现的？
13. TTFT和总延迟，你优化哪个？为什么？

生产与用户:
14. SLO怎么定的？错误预算烧完了怎么办？
15. 单请求成本怎么算的？降了多少？靠什么？
16. 用户说答案错了，你的排查路径？(request_id→trace→节点)
17. 最难的一个BadCase？(准备一个完整故事!)
18. 如果用户量×100，架构哪里先崩？
```
