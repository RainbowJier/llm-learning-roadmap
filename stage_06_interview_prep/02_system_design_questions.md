# 系统设计题精讲

> 周次：Week 2-4 ｜ 投入：30小时

---

## 目标

掌握大模型应用岗系统设计的**标准答题框架**，并把五道高频题练到白板级熟练。你不需要新知识——所有素材都在前五个阶段的项目里。

---

## 答题框架（45分钟白板的节奏）

```
0-5min   需求澄清（主动问！这是加分项不是拖延）
           功能范围/用户量/QPS/延迟要求/成本约束/一致性要求
5-10min  估算与约束
           QPS→并发→LLM调用量→成本→瓶颈初判
10-25min  架构主体（边画边讲）
           分层：接入层→编排层→检索层→生成层→数据层→监控
25-35min 深挖三个难点（考官真正想听的）
           检索质量 / 稳定性 / 成本，各给方案+trade-off
35-42min 故障与演进
           单点故障在哪 / 扩容路径 / 多租户隔离
42-45min 总结一句话
```

**心法**：大模型应用设计题 = 传统后端设计题 + 三个新维度（**概率性、成本、评估**）。主动把这三个词说出来，就和80%的候选人区分开了。

## 高频题一：设计一个支撑百万日活的企业知识库问答（最重要，精练）

### 需求澄清（要问的问题）

```
日活100万，人均5问 → 5M QPS？不，峰值QPS≈ 日请求/86400×峰值系数3 ≈ 170/s
（敢做这个估算并讲出来，面试官眼睛会亮）
延迟要求？答案质量要求？预算？文档更新频率？权限隔离？
```

### 架构（白板草图）

```
客户端 → LB → API网关(鉴权/限流/计费)
              → 多级缓存(精确→语义)
              → 查询服务(改写/意图)
              → 检索集群(向量分片 + BM25集群 + Rerank池)
              → 生成服务(模型路由: haiku/sonnet)
              → 流式返回(SSE)
数据面: 文档更新管道(CDC→解析→重嵌入→增量索引)
       缓存层(Redis: 答案/embedding)
控制面: 监控(SLO/成本/质量抽样评估) 配置中心 灰度
```

### 三个必讲的深挖点

**① 检索层的规模设计**
```
1亿chunk: 单机Chroma不行 → Milvus分片+副本
向量索引HNSW: 召回率98%@毫秒级, 内存≈原始向量×1.5
多租户权限: 向量元数据带租户ID, 检索时过滤(而非库隔离→成本高)
             敏感租户独立collection
```

**② 稳定性**
```
LLM供应商双活: 主备自动切换(复用我项目的熔断+降级阶梯思想)
降级链: 完整→模板→FAQ, 最底层人工工单
重试策略: 只对瞬态错误, 带抖动(讲出为什么: 防重试风暴)
```

**③ 成本（大模型应用独有，必讲）**
```
日均5M请求:
  缓存命中40% → 3M次LLM调用
  模型路由: 70%简单题走小模型
  Prompt缓存: 系统前缀命中
  估算: 单请求$0.003 → 日成本$9K → 必须讲"每用户日均成本"和ROI
  （我在项目里实测过$0.003/请求, 方法完全一致, 只是规模问题）
```

### 收尾总结句

*"这个系统的本质是：用确定性工程包住概率性组件——缓存和索引保证检索确定性，工作流和容错保证行为确定性，评估和监控保证质量可观测。"*

## 高频题二：Agent客服系统（支付/退款场景）

在题一基础上追加三个考点：

```
① 写操作安全: 三段式(意图确认→参数确认→执行)+幂等键+可撤销窗口
   （复用Stage 3-05工具设计原则，举confirm参数的例子）
② 多轮状态: 会话状态机+LangGraph checkpointer(讲人机interrupt: 金额>阈值人工审核)
③ 审计: 每步决策落库(谁/为什么/依据什么上下文), 出纠纷可回放
```

## 高频题三：多文档/长文档理解系统

```
考点: 分层摘要(地图式reduce) / 长上下文与RAG的trade-off
答: 上下文再长也解决不了"哪段相关"的检索问题+成本问题
    → 混合: 先RAG定位章节, 再长上下文精读(父子文档就是雏形)
```

## 高频题四：实时更新的RAG（文档分钟级变更）

```
CDC监听文档变更 → 增量解析(只处理diff) → 双写新索引
→ 蓝绿切换collection别名(原子) → 旧版本TTL回收
一致性: 检索带version标签, 答案标注"依据X版本"
（我项目里effective_year元数据就是简化版这个方案）
```

## 高频题五：评估平台设计

```
考点: 你做过评估就能降维打击
在线: 用户反馈(👍👎+纠错)→badcase池→人工归因→测试集
离线: 每次发版跑回归四指标+意图准确率, 版本对比报表
线上抽样: 1%流量双跑新旧版本对比(LLM-as-judge+人工抽检)
```
